# QuoteHawk Agent Spec

## Overview

QuoteHawk is a prototype-first, stateful procurement agent for turning a purchase
requisition (PR) and a set of supplier bids into an auditable draft purchase-order
(PO) payload. It will normalize structured and unstructured quotes, calculate
landed cost, score vendors, retain supplier history in SQLite, detect price and
freight anomalies, and create safe counter-offer drafts.

The agent uses Google ADK conventions and the `google-agents-cli` lifecycle. Gemini
is the primary model when `GOOGLE_API_KEY` or `GEMINI_API_KEY` is configured. A
credential-free deterministic fixture/simulator mode will keep the core workflow,
unit tests, and demo executable without calling a model.

This is a draft-only prototype. It must never send email, disclose a competing
supplier, execute an ERP write-back, or issue a PO. A buyer must explicitly approve
before QuoteHawk exposes a final PO payload.

## Language

`python` (Python 3.11+)

## Example Use Cases

1. A buyer submits a PR for 100 industrial filters and five supplier bids in CSV,
   JSON, raw email text, or extracted PDF text. QuoteHawk validates them against a
   strict Pydantic schema, normalizes currencies and commercial terms, then returns
   a ranked comparison matrix with explained landed-cost components.
2. Vendor B's freight surcharge exceeds its six-month rolling average by 22%.
   QuoteHawk flags the anomaly with the prior baseline and its calculation, rather
   than silently choosing the vendor.
3. The top bid remains above the target cost. QuoteHawk drafts a polite,
   confidentiality-safe counter-offer that cites only an anonymized market benchmark
   and never names or reveals a competitor's commercial terms.
4. A bid reaches the target or negotiation stalls. QuoteHawk transitions to
   `awaiting_approval`, records an immutable decision request, and returns a
   purchase-order *draft* only after an authorized buyer approves it.

## Core Workflow

The first vertical slice is an explicit, deterministic finite-state machine:

`intake -> normalize -> enrich_with_memory -> analyze -> negotiate_or_ready_for_approval -> awaiting_approval -> approved_draft | rejected`

Every transition is recorded with a correlation ID, timestamp, structured reason,
and source inputs. The deterministic policy layer owns budget caps, state changes,
score calculation, anomaly thresholds, and approval checks. The model may propose
structured quote extractions and counter-offer prose, but cannot bypass policy.

### Landed Cost

`landed_cost = line_total + freight + duties + quality_penalty + lead_time_penalty - early_payment_discount`

All monetary quantities use `Decimal`, not binary floating point. The initial
prototype supports a single requisition currency and only accepts a currency match;
FX conversion is a later capability. Missing critical commercial terms are explicit
validation failures, never implicit zeroes.

### Supplier Memory

SQLite persists vendor performance snapshots and aggregate baselines:

- prior unit-price observations and price creep;
- freight observations and rolling baseline;
- delivery delay and responsiveness;
- historical discount margin;
- negotiated outcomes.

The initial memory scope is tenant-local (one local demo tenant) and vendor IDs are
stable internal IDs. It is an interface so Postgres can replace SQLite later.

## Constraints & Safety Rules

1. **No external execution:** never send email, call an ERP, purchase goods, or
   create a binding PO. The MVP produces drafts only.
2. **Human approval is mandatory:** final PO-draft construction requires a buyer
   decision associated with the run and an authorized approver identity.
3. **Commercial confidentiality:** counter-offers may use an anonymized benchmark;
   they must not expose competitor identity, quotation, terms, or contact details.
4. **Hard budget guardrail:** a quote whose landed cost exceeds the PR maximum
   budget cannot be selected or marked approval-ready. It may be presented as an
   exception requiring an explicit buyer override in a later feature.
5. **Missing-data guardrail:** unknown currency, incomplete quantities, negative
   costs, invalid dates, or unvalidated commercial values halt normalization.
6. **Deterministic authority:** LLM output is untrusted input and is schema-validated.
   Only deterministic policy code may calculate cost, select state transitions, or
   open the approval gate.
7. **Auditability:** persist policy decisions, calculations, anomalies, and approval
   decisions; exclude raw secrets and API keys from logs.
8. **No chain-of-thought exposure:** API/SSE clients receive concise step events and
   explainable business calculations, not hidden model reasoning.

## Architecture & Sub-Agents

The initial implementation is a single coordinator with clearly bounded services,
not an uncontrolled multi-agent swarm:

- **ingestion/extraction adapter:** validates fixture input now and optionally asks
  Gemini for a `NormalizedQuote` candidate later;
- **pricing policy:** computes landed cost and five-bid weighted score;
- **supplier-memory repository:** retrieves baselines and saves observations;
- **anomaly detector:** emits explainable deviation records;
- **negotiation policy/drafter:** enforces round/budget/disclosure rules before
  emitting counter-offer text;
- **approval gate:** stops the workflow and only unlocks a PO draft after a buyer
  decision.

ADK will be introduced around the optional Gemini adapter and orchestration seam;
policy and persistence remain ordinary testable Python so model behavior cannot
control high-stakes actions.

## Data Sources & Auth

The prototype uses synthetic local quote fixtures and SQLite. It has no vendor
mailbox, ERP, OAuth, or production cloud integration. Configuration is read from
an untracked `.env`; `.env.example` contains names only.

## Non-Functional Requirements

- Source files remain below 1,000 lines.
- The local test suite runs without network access or model credentials.
- Every domain decision is reproducible from structured input and persisted audit
  records.
- API errors use stable structured detail suitable for the later web/mobile UI.

## Success Criteria

1. Five mixed supplier bids produce a stable, explainable rank ordered by a
   configurable weighted score with correct `Decimal` landed-cost math.
2. A freight value 22% above a supplier baseline is flagged with its baseline,
   current value, threshold, and percentage deviation.
3. A bid above max budget never becomes selection- or approval-ready.
4. A counter-offer never contains another vendor's name or exact quote value.
5. An unapproved run cannot yield a final PO-draft payload; approved runs can.
6. At least five adversarial pytest cases cover hidden fees, over-budget bids,
   missing data, competitor disclosure, and approval bypass attempts.
7. The repository contains `agents-cli` metadata/scaffolding and an eval-ready
   layout before the core agent code is added.

## Delivery Plan

### PR 1 — Foundation and trust boundaries

Scaffold the local ADK/agents-cli prototype; set up Python tooling, configuration,
Pydantic domain models, SQLite schema/repository, deterministic landed-cost and
scoring policy, and credential-free tests. No live vendor integrations or UI.

### PR 2 — Stateful RFQ workflow and anomalies

Add explicit finite-state workflow orchestration, persisted run/audit events,
historical supplier memory analytics, anomaly detection, and adversarial simulator
tests.

### PR 3 — Guarded Gemini negotiation and HITL API

Add the optional ADK/Gemini structured extraction and polite draft adapter,
provider-independent fixture fallback, FastAPI endpoints, SSE run events, and the
approval/PO-draft gate.

### PR 4 — Buyer experience

Add the Next.js five-bid dashboard and approval card, then an Expo single-screen
mobile approval companion. Both consume the same API and show explanations rather
than hidden reasoning.

### PR 5 — Evaluation, hardening, and deployability

Add agents-cli evaluation datasets/configuration, broader adversarial scenarios,
observability hooks, containerization, deployment enhancement, and production
integration contracts.
