# QuoteHawk Agent Spec

## Overview

QuoteHawk is a stateful, guarded procurement agent for turning a purchase
requisition (PR) and a set of supplier bids into an auditable draft purchase-order
(PO) payload. It normalizes three-to-fifty CSV, plain-email, and PDF supplier
artifacts (or already-normalized fixtures), calculates landed cost, scores
vendors, retains supplier history in SQLite/Postgres, detects price and freight
anomalies, and creates safe counter-offer drafts.

The agent uses Google ADK conventions and the `google-agents-cli` lifecycle. Gemini
is the primary model when `GOOGLE_API_KEY` or `GEMINI_API_KEY` is configured. A
credential-free deterministic fixture/simulator mode will keep the core workflow,
unit tests, and demo executable without calling a model.

QuoteHawk is draft-only. It must never send email, disclose a competing
supplier, execute an ERP write-back, or issue a PO. A buyer must explicitly approve
before QuoteHawk exposes a final PO payload. The API can verify an existing OIDC
bearer token and derive the buyer/tenant/roles server-side; it does not host an
OAuth login, provision an identity provider, or grant execution capability.

## Language

`python` (Python 3.11+)

## Example Use Cases

1. A buyer submits a PR for 100 industrial filters and three to fifty supplier bids
   in CSV, plain email text, or base64 PDF form. QuoteHawk discards the raw artifact
   after strict Pydantic normalization, validates currencies and commercial terms,
   then returns a ranked comparison matrix with explained landed-cost components.
2. Vendor B's freight surcharge exceeds its six-month rolling average by 22%.
   QuoteHawk flags the anomaly with the prior baseline and its calculation, rather
   than silently choosing the vendor.
3. The top bid remains above the target cost. QuoteHawk drafts a polite,
   confidentiality-safe counter-offer that cites only an anonymized market benchmark
   and never names or reveals a competitor's commercial terms.
4. A bid reaches the target or negotiation stalls. QuoteHawk transitions to
   `awaiting_approval`, records an immutable decision request, and returns a
   purchase-order *draft* only after an authorized buyer approves it.

## Core Workflow

The first vertical slice is an explicit, deterministic finite-state machine:

`intake -> normalize -> enrich_with_memory -> analyze -> negotiate_or_ready_for_approval -> awaiting_approval -> approved_draft | rejected`

Every transition is recorded under its RFQ run ID with a timestamp, structured
reason, and source inputs. HTTP request/run correlation is emitted separately as
safe local structured observability data. The deterministic policy layer owns
budget caps, state changes, score calculation, anomaly thresholds, and approval
checks. The model may propose structured quote extractions and counter-offer prose,
but cannot bypass policy.

### Landed Cost

`landed_cost = line_total + freight + shipping + duties + quality_penalty + lead_time_penalty + MOQ_penalty + payment_term_penalty - early_payment_discount`

All monetary quantities use `Decimal`, not binary floating point. Supplier bids
may use a different currency only when the request includes an explicit,
auditable rate from the supplier currency into the requisition currency; QuoteHawk
never guesses, fetches, or silently reverses FX. Missing critical commercial terms
are explicit validation failures, never implicit zeroes. Freight, shipping, and
duties are separate required values (each may be explicitly zero); lead-time, MOQ,
and declared Net/prepayment/milestone/letter-of-credit effects are deterministic
policy inputs. Payment-term fit is a buyer preference: each requisition records a
target payment day (defaulted to Net 30 when legacy requests omit it), scores 100
at that target, and declines with absolute distance from it. The longest supplier
term is never used as a payment-score benchmark.

### Supplier source ingestion

`POST /api/rfq/source-runs` accepts three through fifty source artifacts
for one requisition. The active policy defaults to 20 bids and is configurable up
to the hard transport ceiling of 50; the buyer matrix pages five bids at a time.
The credential-free `rule_based` provider parses a strict
CSV contract and labeled plain email/text-PDF contract; a configured Gemini
provider may normalize less regular unstructured email or PDF content. PDF bytes
are bounded, base64 encoded, and never persisted. The raw source artifact is
removed after normalization; only strict normalized facts and a one-way
idempotency fingerprint may become durable data. No mailbox polling, OCR service,
vendor communication, or document archive is added.

### Supplier Memory

SQLite persists local-demo vendor performance snapshots and aggregate baselines;
the explicit Postgres backend preserves the same tenant-scoped semantics:

- prior unit-price observations and price creep;
- freight observations and rolling baseline;
- delivery delay and responsiveness;
- historical discount margin;
- negotiated outcomes.

Memory is tenant-local and vendor IDs are stable internal IDs. SQLite remains the
credential-free demo backend; the Postgres backend uses reviewed migration SQL,
transaction-local tenant binding, and row-level security. When explicitly
configured, Redis provides the supplier-baseline cache and a safe RFQ work-signal
queue; it carries no raw artifacts or commercial request bodies and never silently
falls back if unavailable. It is installed only with the optional `redis` extra and
is required only when `QUOTEHAWK_REDIS_URL` is set. The Postgres backend borrows
connections from a bounded, lazy `psycopg_pool` pool and sets RLS tenant context
per transaction. Database and
Redis provisioning remain explicit deployment-owner responsibilities.

## Constraints & Safety Rules

1. **No external execution:** never send email, call an ERP, purchase goods, or
   create a binding PO. The MVP produces drafts only.
2. **Human approval is mandatory:** final PO-draft construction requires a buyer
   decision associated with the run and an authorized approver identity. In OIDC
   mode the actor, tenant, and role come from a verified signed token, never body
   input or UI state.
3. **Commercial confidentiality:** counter-offers may use an anonymized benchmark;
   they must not expose competitor identity, quotation, terms, or contact details.
4. **Hard budget guardrail:** a quote whose landed cost exceeds the PR maximum
   budget cannot be selected or marked approval-ready. A documented buyer override
   can select another eligible in-budget bid only; it never bypasses the budget.
5. **Missing-data guardrail:** unknown currency, incomplete quantities, missing
   freight/shipping/duties, negative costs, invalid dates, or unvalidated
   commercial values halt normalization.
6. **Deterministic authority:** LLM output is untrusted input and is schema-validated.
   Only deterministic policy code may calculate cost, select state transitions, or
   open the approval gate.
7. **Auditability:** persist concise policy decisions, calculations, anomalies, and
   approval decisions; local operational logs must exclude bodies, raw supplier
   documents, commercial values, buyer identities, secrets, exception text, model
   traces, and hidden reasoning.
8. **No chain-of-thought exposure:** API/SSE clients receive concise step events and
   explainable business calculations, not hidden model reasoning.
9. **Tenant isolation:** a verified principal may access only RFQ runs, supplier
   history, anomaly baselines, and approval decisions in its token-derived tenant.
10. **Persistence selection:** selecting Postgres requires a reviewed migrated
    database and must never silently fall back to SQLite; the application must bind
    the verified tenant to every Postgres transaction.

## Architecture & Sub-Agents

The initial implementation is a single coordinator with clearly bounded services,
not an uncontrolled multi-agent swarm:

- **ingestion/extraction adapter:** validates fixture input now and optionally asks
  Gemini for a `NormalizedQuote` candidate later;
- **pricing policy:** computes FX-normalized landed cost and a configurable multi-bid weighted score;
- **supplier-memory repository:** retrieves baselines and saves observations;
- **anomaly detector:** emits explainable deviation records;
- **negotiation policy/drafter:** enforces a configurable target threshold and
  disclosure rules before emitting a multi-turn, draft-only simulated email thread;
- **approval gate:** stops the workflow and only unlocks a PO draft after a buyer
  decision; an optional signed, idempotent buyer-approval/override notification
  may be sent after that draft-only decision, never to a supplier or ERP.

ADK will be introduced around the optional Gemini adapter and orchestration seam;
policy and persistence remain ordinary testable Python so model behavior cannot
control high-stakes actions.

## Data Sources & Auth

The system uses synthetic local quote fixtures and SQLite by default. An explicit
Postgres repository can be selected only after its reviewed migration is applied;
it does not provision a database or deploy infrastructure. QuoteHawk has no vendor
mailbox, ERP, OAuth login flow, identity-provider provisioning, or production cloud
integration. In `oidc` mode it verifies a configured provider's bearer JWT against
an HTTPS JWKS endpoint and derives actor/tenant/roles from signed claims.
Configuration is read from an untracked `.env`; `.env.example` contains names only.

## Non-Functional Requirements

- Source files remain below 1,000 lines.
- The local test suite runs without network access or model credentials.
- Production-shaped FastAPI/SQLite integration tests exercise HTTP serialization,
  authentication/tenant boundaries, persistence, and reconnect-safe SSE output.
- Every domain decision is reproducible from structured input and persisted audit
  records.
- API errors use stable structured detail suitable for the later web/mobile UI.
- GitHub Actions runs the locked Python policy/test/type/spelling/package gates,
  agents-cli lifecycle checks, and client type/build/export/audit gates on every
  push and pull request. It uses no credentials and has no deployment step.

## Success Criteria

1. Three to fifty mixed CSV/email/PDF supplier bids produce a stable, explainable
   rank ordered by a configurable weighted score with correct `Decimal` landed-cost
   math, including separate freight, shipping, and duties.
2. A freight value 22% above a supplier baseline is flagged with its baseline,
   current value, threshold, and percentage deviation.
3. A bid above max budget never becomes selection- or approval-ready.
4. A counter-offer never contains another vendor's name or exact quote value.
5. An unapproved run cannot yield a final PO-draft payload; approved runs can.
6. At least five adversarial pytest cases cover hidden fees, over-budget bids,
   missing data, competitor disclosure, and approval bypass attempts.
7. The repository contains `agents-cli` metadata/scaffolding and an eval-ready
   layout before the core agent code is added.
8. Every push and pull request executes the same credential-free Python and client
   quality gates documented for local development, without a CI deployment path.

### PR 7 — Postgres persistence path

reviewed migration SQL, tenant-inclusive relational constraints, transaction-local

as the default credential-free demo backend. Do not provision a database, run a
cloud migration, deploy infrastructure, send vendor messages, write to an ERP, or
create binding purchase orders.

### PR 12 — Supplier source ingestion and complete landed cost

Complete the existing ingestion contract with a bounded three-to-fifty source-run
endpoint for CSV, plain email, and PDF quotations. Add shipping as a separate
explicit landed-cost component alongside freight and duties, retain Net-30/Net-60,
MOQ, and lead-time effects, and verify source-derived runs use the existing durable
supplier-memory baselines. Keep raw artifacts ephemeral; do not add mailbox
